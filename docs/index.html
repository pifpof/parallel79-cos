The Idea

AI that actually remembers.

Most AI tools start from zero every conversation. Your Chief of Staff is different.

Your conversation is working memory.
Your vault is long-term memory.
"Save to memory" is the save button.

When you talk to your Chief of Staff, everything is live — but temporary. When you save to memory, what mattered gets written down permanently. Next time, it's still there. That single habit — start the session, save at the end — is what separates a system that compounds from a very capable chatbot.

Working Memory
Conversation
Live context for this session. Decisions, context, and new information are all here — but temporary.
/save ⟷ /start
Long-Term Memory
Your Vault
Structured Markdown files on your computer. Grows with every session. Queryable, auditable, yours.

Quick Start

Up and running in five minutes.

Follow these steps in order. You only do step one once.

  1. 1

    Install the skill pack

    In any Claude Code or Cowork session, run: /plugin install github.com/parallel79/ai-chief-of-staff
    Or via npx on any platform: npx ai-chief-of-staff-skills

  2. 2

    Create your vault folder

    Create an empty folder anywhere on your computer — e.g. ~/my-chief-of-staff/. Open Claude Code (or your agentic tool) inside it. This folder will become your knowledge base.

  3. 3

    Run /onboard

    Type /onboard. This is a first meeting with your Chief of Staff — not a setup wizard. You'll define how they should work with you, then brief them on your role, priorities, and world. Take your time. The depth of this conversation seeds the quality of everything that follows.

  4. 4

    Start each session with /start

    Every time you open a new session, type /start. Your Chief of Staff reads the vault and opens with a brief on where things stand. You never have to catch it up. Need something more for this particular session — a slow connector check, a calendar pull? Add it right on the command: /start also check our project tracker.

  5. 5

    End each session with /save

    Before you close, type /save. Your Chief of Staff writes what changed — decisions made, priorities shifted, anything new — back to the vault. This is the habit the system depends on. Without it, each session starts from scratch.

The one thing that matters most: The save habit. The single biggest difference between users who get compounding value and users who don't is whether they type /save before closing. A system you don't save to is just a very capable chatbot.

Skills Reference

Eight commands. Complete coverage.

You don't need to memorize these — you'll learn them by using them. Here's the full set.

Getting Started
⭐
Start Here — Once
/onboard
Onboard
A two-phase hiring conversation. First, you define the persona, style, and name of your Chief of Staff. Then you brief them on who you are — your role, organization, priorities, recurring workflows, and key people. At the end, the vault is seeded with your profile and the system is ready to work.

Run this once before any other skill. The depth and specificity of your answers here determine the quality of every session that follows. Don't rush through it.
Tip: If you're vague, the system will be vague. Be specific about your priorities — not "grow revenue" but "close the Series A by Q3 with a lead investor already identified."
Working with your assistant
▶
Daily — Session Start
/start
Start Session
Reads your vault and opens with a sharp brief: where things stand, what's on the radar, and a suggested focus for today. You never have to catch the system up — it already knows what's going on. It's also the one place to go beyond your standing CLAUDE.md rules — add extra instructions right on the command (/start also check our project tracker) when a session needs a slower lookup that shouldn't run by default every time.
When: At the top of every working session. Pair with /save at the end. (Formerly /load.)
💾
Daily — Session End
/save
Save to Memory
Synthesizes everything significant from the session — shifted priorities, decisions made, new context, new people — and writes it back to the vault. Updates the memory index. This is the keystone skill: without it, nothing accumulates.
The rule: Never close a session without typing /save. The system is only as good as what got written back last time.
📎
Ingest
/capture
Capture a Source
Hand it something to remember — a URL, a report, a document, or pasted text. It reads the source, extracts what matters to you specifically, files the raw material in /data, and compiles the knowledge into the wiki with cross-links to existing memory. This is how the library grows.
Examples: A competitor's product update, an industry report, meeting notes from a client call, an article you want to remember.
🔍
Retrieval
/query
Query the Wiki
Ask a question and get an answer drawn from your own accumulated knowledge — not the open internet. "What did we decide about the vendor contract?" "Pull together everything we know about this client." Answers are grounded, coherent, and traceable back to their sources. The longer the system has been running, the better these answers get.
The difference: A query answered from your compiled wiki, informed by months of context, beats anything you'd type into a search engine.
Keeping the memory up to date
🔄
Ingest — Batch
/sync
Sync Sources
Batch version of /capture. Dropped a stack of files into /data without processing them? Run /sync and the system catches up — scanning for unprocessed sources, reading them oldest-first, and compiling everything into the wiki.
When: After a period of offline work, or when you've accumulated several documents you want absorbed at once.
🩺
Maintenance
/lint
Health Check
A tune-up. Scans memory for files missing metadata, stale projects still marked active, orphaned sources that were never compiled, broken lineage, contradictions, and index drift. Fixes what it safely can automatically, and surfaces the judgment calls — the things only you can decide.
When: Weekly or monthly. A clean vault means sharper briefs, better queries, and faster loads. Runs in under a minute.
Stepping back
🔭
Weekly
/review
Weekly Review
A step back. What moved this week, what stalled, what patterns are showing up across projects and weeks, and the single priority for the week ahead with three concrete intentions. Honest by design — a Chief of Staff who only tells you what went well isn't worth having. Self-saves to memory, no separate /save needed.
When: End of week. The patterns section is where the system earns its keep — it sees things across weeks that you're too close to notice.

Vault Structure

Just a folder of files.

Your knowledge base is plain Markdown on your own computer. No lock-in. Human-readable. Survives the tooling.

/data

Raw Sources

Every document, article, or transcript the system has ever ingested. Append-only — nothing is ever edited after it lands. This is the source of truth and the lineage anchor for everything in memory.

/memory

The Wiki

Structured, interlinked Markdown that compiles the raw sources into knowledge. Organized into /profile, /projects, and /library. This is the layer that compounds.

/memory/profile

Your Profile

Who you are, your current priorities, recurring workflows, key people, and working style. Seeded by /onboard and updated by /save as your situation evolves.

/memory/projects

Projects

Active and reference project knowledge. Decisions logged, blockers noted, status tracked. This is where your Chief of Staff holds the thread on everything you're working on.

/memory/library

Library

Retained knowledge, research, reference material, and a decisions log. Written by /capture and /sync as sources are compiled into the wiki.

/outputs

Outputs

Generated content worth keeping — daily briefs, query answers, weekly reviews. Named with dates so your history is auditable.

memory.md

Memory Index

A one-file index of everything in /memory. Every skill reads this first to orient without loading every file. Keeping it sharp is what keeps the system fast as the vault grows.

/trash

Trash

Things removed from context but never hard-deleted. Moving to trash is always preferable to deleting — the cost of keeping a file is near zero; the cost of losing something important is not.

Tip: Visualize your vault in Obsidian. Open the vault folder in Obsidian and your memory becomes a visual graph you can browse and click through. You don't need it to use the system — but it's a satisfying way to watch your knowledge base grow.

Getting the Most Out of It

Four habits that make the difference.

The system rewards consistent use. These are the behaviours that separate a compounding knowledge base from an expensive chat window.

01

Save, every time.

The single biggest difference between users who get value from this system and users who don't is the save habit. If something significant happened in a conversation — a decision, a new priority, new context — save it before you leave. A system you don't save to is just a chatbot.

02

Feed it what matters.

The more you capture, the smarter the system gets. When you read something that matters to your business — a competitor's announcement, a market report, notes from a key meeting — hand it over with /capture. Every source makes every future answer sharper.

03

Talk to it like a colleague.

It has context. Use it. "What should I be worried about going into the board meeting?" is a better question than anything you'd type into Google — because it knows your board, your business, and your last three months. Ask questions you'd ask a trusted senior colleague who knows everything.

04

Let it push back.

A good Chief of Staff doesn't just take orders — it notices patterns, flags what's being avoided, and tells you what you might not want to hear. The weekly review is designed to be honest with you. Don't soften the brief by only asking easy questions.

Under the Hood

The architecture that makes it compound.

No vector database, no embeddings, no vendor lock-in. Just Markdown files and an index.

/data Append-only · Source of truth
Raw sources. Every document, article, or conversation that enters the system lands here first. Never edited after arrival — this is the audit trail. Any memory file can be traced back to a raw source in this folder.
/memory LLM-maintained · Compounds over time
The compiled wiki. Structured, interlinked Markdown that distills the raw sources into knowledge. The model reads it, writes to it, and updates it — but it's also human-readable. If the AI tooling disappears tomorrow, the knowledge survives. This is the Karpathy LLM wiki pattern: compile knowledge ahead of time, not at query time.
CLAUDE.md Schema · Persona · Rules
The schema. Defines who your Chief of Staff is, how the vault is structured, the rules it operates by, and the full skill list. This is the highest-leverage file in the system — most customization happens here. Every session starts by reading this file.
memory.md Index · Read first
The index. Every skill reads this file before loading anything else. One-line summaries of every memory file let the model orient across the entire vault without loading every file. This is what keeps token usage flat as the vault grows — the system gets smarter without getting slower.

Memory File Contract

Every memory file starts with this block.

Breaking this contract degrades every skill that reads memory. Never create a file in /memory without it.

---
title:    "Current Priorities"

sources:  ["onboard", "session — 2026-06-26"]

Maintenance

Keeping the vault healthy.

A vault left without maintenance slowly degrades. Most issues have simple fixes — and almost all of them start with one of three root causes.

The three most common problems, in order: The memory index is stale. A source wasn't compiled (orphaned file in /data). The executive stopped saving. Check these first before anything else.
Symptom Likely Cause Fix
Vault feels slow or unfocused memory.md is bloated or stale Run /lint. Trim index entries to sharp one-line summaries.
Queries returning thin or generic answers Sources in /data were never compiled Run /lint to identify orphaned sources, then /sync to process them.
Memory contradicts itself Two files have conflicting facts /lint surfaces it. You pick the correct version. Move the wrong one to /trash with a note.
Session doesn't pick up where I left off /save wasn't run at end of session Nothing to recover — the conversation was working memory only. Run /save going forward. It takes 30 seconds.
Profile feels out of date Role or priorities evolved, files weren't updated Open a session, update your Chief of Staff on what changed, then run /save. Or tell it directly in any session.
Need to recover something removed File was moved to trash Check /trash — nothing is ever hard-deleted. Files there have a note explaining why they were removed.

Extensibility

Build skills for your specific role.

The eight baseline skills cover the core loop. Role-specific skills are where the system truly diverges — and where the real leverage lives.

1

Create a skill folder

Inside the .claude/skills/ directory (for project scope) or ~/.claude/skills/ (global), create a folder named after your skill. Inside it, create SKILL.md.

2

Write the frontmatter first

The description field is the triggering mechanism — Claude reads it to decide whether to use the skill. Be generous: list the slash command and the natural-language phrases someone would actually say.

Weak: "Generates a board report."
Strong: "Use when the user says '/board-report', asks to prepare a board update, wants to generate a board deck, or needs to summarize progress for investors."

3

Write the body in imperative voice

"Read the vault." Not "The skill should read the vault." Explain why each step matters, not just what to do — skills that understand the why produce better judgment. Always read memory.md first; always update it if you write anything new.

4

Test against real prompts, then drop it in

Try 2–3 realistic phrases you'd actually say. If it doesn't trigger, the problem is almost always in the description — expand the trigger phrases. Once it triggers correctly, the skill is live immediately. No restart needed.

Give the system a month of consistent use — loading in, saving out, capturing what matters — and it becomes something you'd struggle to work without. Every session adds to it. Every decision you log becomes history you can draw on. Every source you capture makes the next answer sharper.
